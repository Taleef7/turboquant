# TurboQuant CUDA setup

Use a native WSL Linux checkout and Python 3.11 or newer. Do not use nightly
PyTorch builds: `requirements/runtime.lock` is generated from a verified stable
CUDA 12.8 environment and pins the complete runtime set.

```bash
git clone https://github.com/Taleef7/turboquant.git
cd turboquant
python3.12 -m venv ~/.venvs/turboquant-forge
source ~/.venvs/turboquant-forge/bin/activate
python -m pip install --upgrade pip
python -m pip install -r requirements/runtime.lock
```

Confirm both the host driver and the installed CUDA wheel before any benchmark:

```bash
nvidia-smi
python -c "import torch; print(torch.__version__); print(torch.version.cuda); print(torch.cuda.is_available()); print(torch.cuda.get_device_name(0) if torch.cuda.is_available() else None)"
python -c "import accelerate, bitsandbytes, einops, numpy, safetensors, scipy, transformers, triton; print('runtime imports: OK')"
```

CPU-only contract tests never allocate CUDA tensors or download models:

```bash
python -m pip install pytest ruff
python -m pytest tests -m "not gpu" -q
python -m compileall core scripts tests
```

If `torch.cuda.is_available()` is false, check `nvidia-smi` inside WSL first;
the pinned CUDA 12.8 wheel requires a current NVIDIA WSL driver. The lock must
only be regenerated by the command recorded in its header after the CUDA smoke
test succeeds.
